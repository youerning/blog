# 内网穿透工具实测 · 执行计划

> 目标文章：《内网穿透工具对比》——不是 star 排行榜，是「同一件事用不同工具做，代价差多少」的实测。
> 两台真机：阿里云广东（203.0.113.10）、UCloud 香港（203.0.113.20），都开了 60000–61000 TCP/UDP。
> 状态：**待批准**。批准后才开始装东西。

**可达性矩阵**（实测，非推测）：

| 从哪 | 到 广东:22 | 到 广东:60000-61000 | 到 香港:22 | 到 香港:60000-61000 |
|---|---|---|---|---|
| 本地 Mac（出口 27.38.189.143，深圳联通） | ❌ **超时** | ❌ 超时 | ✅ | ✅（快速 refused = 放行） |
| 香港主机 | — | ✅（快速 refused = 放行） | — | — |

香港 → 广东：ICMP 通，**RTT 11.5 / 16.3 / 20.0 ms（min/avg/max，5 包 0 丢）**。这条跨境链路质量不错，适合做延迟实验。

### ⚠️ 阻塞点：广东主机的 22 端口现在不通

- 我一共连了 4 次：**第 1 次成功**（拿到了 uname 和内存），之后 3 次全部 `Operation timed out`
- 从香港侧试广东 22 也是超时，但 60000 段是「connection refused」（= 可达、没人监听）
- 说明不是机器挂了、也不是安全组整体封我，而是 **22 被单独过滤**了（可能只对某个白名单 IP 放行，或者云盾把 TCP 拦了、ICMP 还放着）

**需要你做的（二选一）**：
1. 阿里云控制台 → 轻量应用服务器 → 防火墙 → 确认 22/tcp 对 `0.0.0.0/0` 放行
2. 或者告诉我该加哪个 IP，我现在的出口是 **27.38.189.143（深圳联通）**——如果你是按 IP 白名单放的，加这个就行

在这之前，广东那台什么也做不了；香港那台可以先做准备工作（装包、下二进制）。

## 1. 要回答的问题（文章骨架就靠这五个）

| 编号 | 问题 | 为什么值得问 |
|---|---|---|
| Q1 | **从零到跑通要多久、多少行配置？** | 这是大多数人真实的门槛，比吞吐重要 |
| Q2 | **常驻吃多少内存？** | 2C2G 小机器上，选错工具就是选错整台机器 |
| Q3 | **延迟增加多少？**（相对不挂隧道的直连） | 跨境场景最敏感的就是这个，不是吞吐 |
| Q4 | **单流吞吐能跑多高？** | 云主机带宽是硬上限，工具能不能跑满 |
| Q5 | **特性差在哪？**（UDP / 加密 / 多路复用 / 断线重连 / 鉴权） | 决定它适不适合你的场景 |

**明确不做的**：不做高并发压测（2C2G 先崩的是机器不是工具）、不做长期稳定性（至少跑一周才有意义）、
不测商业产品（Ngrok 付费版、花生壳）、不评"哪个最好"——只给"什么场景选哪个"。

## 2. 被测对象（6 个中继式 + 2 个边缘托管，共 8 个）

下载前一律现查 star / license / 最后提交，避免引用过期数字。

### A 组 · 中继式（需要一台公网机器，全部可完整测）

| 工具 | 语言 | 备注 |
|---|---|---|
| frp | Go | 事实标准，配置最啰嗦 |
| rathole | Rust | 主打省内存，TOML 配置 |
| chisel | Go | HTTP/WebSocket 单端口复用 |
| nps | Go | **2024-05 停更**，但仍被大量推荐，必须点名 |
| sish | Go | SSH 反向隧道 + 自动 HTTPS |
| bore | Rust | 极简，只有一条命令 |

### B 组 · 边缘托管（不需要自己的机器，但受限）

| 工具 | 限制 |
|---|---|
| cloudflared（quick tunnel） | 不登录就能起临时域名；**国内出口能不能连上要实测**，这是文章里最有信息量的一条 |
| localtunnel | 需要 Node + npm，公共服务器在国外 |

### 明确不测 · 组网式（Tailscale / EasyTier）

2026-11-21 决定放弃，理由是三条：

1. 它们**不是同一类东西**——本质是"把设备拉进同一个虚拟局域网"，不是"把端口暴露出去"，
   混在一张吞吐表里比只会误导读者
2. 都要账号/控制平面，无法全自动复现，别人照着脚本跑不起来，违背本实验"可复现"的前提
3. 在 2C2G 小机器上它们的资源数据没有代表性

**替代做法**：文章里保留一节"为什么我没把它们放在一起比"，用一段文字把三类东西的分界讲清楚
（中继式 / 边缘托管 / 组网式），这比硬塞两个测不准的数字有价值。

## 3. 拓扑与端口分配

```
        ┌─ 探测端 ────────────────────────────────────┐
        │ ① 香港本机（同机探测，排除跨境变量）        │
        │ ② 本地 Mac（真实跨境链路，出口深圳联通）    │
        └───────────────┬─────────────────────────────┘
                        │ TCP/UDP 60xxx
              ┌─────────▼─────────┐        隧道        ┌──────────────────┐
              │ 阿里云广东（公网）│ ───────────────▶ │ UCloud 香港      │
              │ frp/nps/... 服务端│                   │ 客户端 + 被测服务 │
              └───────────────────┘                   └──────────────────┘
```

**默认方向**：服务端在广东（国内低延迟入口），客户端在香港（模拟"内网里的机器"）。
另外对 **frp 和 rathole 各补一次反向**（服务端香港、客户端广东），用来回答"方向是否影响结果"，
不全部翻倍——那只会把时间翻倍而不增加信息量。

## 4. 每个指标怎么量（脚本化，可复现）

| 指标 | 方法 | 采样 |
|---|---|---|
| **直连基线** | 香港起 iperf3 -s 在 61000，广东直连打 | 3 次取中位 |
| **延迟增量** | 自写 TCP ping-pong（发 10 字节、收 10 字节 × 200 次），按隧道前后相减，报 p50/p95/p99 | 3 轮 |
| **吞吐** | `iperf3 -t 10 -P 1`（单流，反映真实单连接体验）；再跑一次 `-P 4` 看多流 | 3 次取中位 |
| **内存** | 空载静置 60 秒后 `ps -o rss=`；再加跑吞吐时的峰值 | 2 个数 |
| **CPU** | 吞吐过程中 `pidstat -p <pid> 1 10` 取均值 | 1 次 |
| **部署成本** | 我边做边记：几条命令、几行配置、卡了几次 | 流水账 |
| **断线重连** | kill 服务端进程 → 计时到隧道恢复可用（curl 打通） | 3 次 |
| **特性** | 配置项 + 官方文档取证；UDP 支持必须实测（`iperf3 -u`），不采信 README | — |

**所有数字带方差**：每项 3 次，报中位数 + 区间。文里绝不写单一数字假装精确。

## 5. 执行阶段

| 阶段 | 内容 | 预估 |
|---|---|---|
| **P0 前置** | 等你放行广东 22；两台装 iperf3 / pidstat；时间同步确认；先跑 20 分钟链路基线（每 5 分钟一次 RTT，看抖动） | 20 min |
| **P1 基线** | 直连吞吐（1/4 流）、直连 RTT、首字节时间。**没有这个后面所有数都没意义** | 20 min |
| **P2 A 组** | frp → nps → rathole → chisel → bore → sish，每个固定流程走一遍 | 2 h |
| **P3 B 组** | cloudflared 重点测"国内能不能连上"；localtunnel | 25 min |
| **P4 整理** | 汇总 CSV、画 6–8 张图（走 hugoblog 的 `make_figs.py`） | 40 min |
| **P5 写文章** | 先写回选题文件，再扩正文（下一轮，不在本次） | — |

**合计约 3 小时**（不含写文章）。去掉组网式那一组省了 40 分钟。中途会请你点一次：如果 cloudflared 在国内完全连不上，

## 7. 风险与红线

| 风险 | 处理 |
|---|---|
| **nps 停更 1.5 年，有历史 RCE** | 只在测试期开，用 60002 高端口 + 16 位随机口令，测完立刻 kill 并关安全组端口 |
| 跨境链路按小时波动，晚上和白天能差一倍 | 记录每次测试的时刻；晚间（21–23 点）对 frp/rathole 各补测一轮做对照 |
| 云主机带宽/流量计费 | **总流量上限 15 GB**，iperf3 单项不超过 500 MB；测完清理所有二进制和日志 |
| 被误判为攻击/滥用 | 只用 60000–61000 自开端口，不做扫描，不对第三方发起任何请求 |
| 合规 | 只做端口转发与性能对比，不涉及任何规避网络管理用途；cloudflared 那节如实写国内可用性限制 |
| 断线测试要 kill 进程 | 只 kill 我这次起的进程（统一带 `bench-` 前缀和独立用户），不碰机器上已有服务 |
| 两台机器上可能有你别的服务 | P0 先做一次现状快照（`ss -lntup`、docker ps），全程不动已有端口 |
